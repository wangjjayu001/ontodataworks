# 智能问数目录回退与来源展示设计

日期：2026-11-23。状态：实施中；执行范围与检查结果见[实施计划](../plans/2026-11-23-agent-metadata-recall-results-plan.md)和[验收报告](../reports/2026-11-23-agent-metadata-recall-results.md)。

## 问题与用户触发条件

用户提出结构化问数，Codex CLI 返回的模型目录/阶段输出与后端注册契约不同步时，用户可能看见笼统的模型不可用错误。在语义 Release 内没有可以唯一匹配的已发布 Metric/Binding 时，即使用户能读取实际目录与字段，链路也会停在“无证据”，没有形成可澄清的下一步。查询成功后，技术检查码、物理来源及其固定快照不适合中文用户复核；聚合 SQL 的空集零结果也必须和有记录的零值区分。

## 原则与交互

Codex CLI 与 API 之间使用同一版本化 `semantic-model/1.2` 契约，分别对 intent、clarification、explain 和 metadata-candidate 的请求/响应字段与 Schema 散列作核对。旧 bridge 或结构不符显示为精确契约错误，不能静默按新结构重解释。

运行始终固定 Release、IndexSnapshot 和 CatalogSnapshot。语义无命中时，后端按当前用户/空间回查固定目录及权限允许的表字段；目录召回只是元数据候选，不冒充业务定义或语义证据。用户补充统计对象和计算口径后，模型只从服务端提供的明确字段 ID 中提出单表参数化计划。后端核实字段、类型、筛选、单位、时间范围及固定版本，展示口径卡供用户确认，再由确定性编译器生成只读预览。不能由目录证明的事项继续提问或阻断。候选只绑定本次运行，不创建语义资产，不自动批准，也不得带入模型 SQL。

执行结果由现有 QueryFrame、Gate 和一次性授权状态机产生。成功响应分组显示行列明细、中文检查项目及结果、临时候选/固定 Metric 和 Binding 修订、来源表与字段、目录快照、数据批次、字段释义以及可展开的归档原文和核验回执。读取历史明细及来源时再次应用当前空间和物理/语义权限。底层技术码可供展开查看，业务文案优先使用服务端给出的标签。

聚合结果另用与主查询相同目录快照、时间范围和筛选值的观测 SQL 检查有效源记录。这样数据库 `COUNT(*)` 或 `COUNT(DISTINCT ...)` 输出的一行 `0`，在源数据集合为空时仍会显示无数据；存在有效源记录的 `0` 会保留。结果原值、空值、截断及技术/业务边界均如实展示。

## 契约及权限边界

语义资产权威仍是 `AssetRevision + CatalogSnapshot`。召回结果、元数据候选和推断出来的口径不是等价授权；候选不得更改 Release/Deployment 或物理目录引用。每一个候选表和字段都在建立候选、确认动作、Gate、执行和历史查看边界受现时权限约束。模型只能选择精确返回的 ID，编译、SQL 审核、当前表结构、只读账户和成本/行数门槛由后端校验。

部署仅扩大已记录的本地合成数据验证能力。既有生产 Agent 禁用状态、数据分类、一次性授权、状态 CAS、只读和不重放约束不变。`result.provenance` 和校验内容采用向前兼容的可选字段，不增加数据库表，也不修改已有 Release/QueryFrame 权威版本。

## 检查策略

检查模型目录与阶段 Schema 的成功/过期/不匹配响应；验证真实语义检索无 Metric 命中后仍可按权限读取固定快照目录；验证澄清答案之后的 metadata candidate 确认、SQL AST 编译及候选字段/参数边界；验证记录数和去重计数的零值/空集分支；验证结果来源权限、证据展示与中文状态。运行存量 Python、前端测试、仓库检查与真实本地 CLI 结构化阶段。真实 PostgreSQL 与浏览器链路仅在有当前运行证据时标记通过。
