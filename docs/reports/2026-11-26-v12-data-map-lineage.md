## 本机真实接口与页面

指定 independent-workbench 部署逐文件备份后更新前端与 API，保留 PostgreSQL 卷，无数据库迁移。模型 bridge 重启并读取本机当前 CC Switch 配置；本轮不调用真实模型生成新问题。HTTPS 证书由本机 CA 正常验证，没有关闭校验。

`scripts/validate_catalog_lineage_live.py --runtime-root <已配置部署目录>` 使用本机凭据完成普通/访客登录，访问正常电商空间 3 与访客副本空间 19。两边均为 42 张表；订单标准表返回 51 个表/查询节点、71 条表关系、51 条字段关系、36 条解析记录，状态为成功查询来源及重算一致。这里包含历史查询，前端默认表间加工只加载对应子集。接口检查还覆盖两层展开、关闭查询结果、跨空间表 404、跨空间权限 403、访客模型 403。脚本会创建和退出验收会话，不修改源表或执行历史 SQL。

浏览器验证正式空间和访客表工作页、表级/字段级页签、order_id 值依赖、上游表跳转及 SQL/表达式证据。实际窗口宽度约 1280 与较窄面板均检查；画布独立滚动、页签可横向滚动。字段筛选仅保留相关节点；共同参与某个下游任务的另一输入不会被当成当前表的上游祖先。

问数使用实际 SmartQuery 组件和隔离请求夹具，模拟确认口径后 CONNECTING → MODEL_RUNNING → VALIDATING。在 22 条已澄清条件的长卡片中，确认后进度卡定位到消息容器顶部附近；手动滚动至历史内容后，多次轮询不再抢回位置。此项是实际浏览器交互验证，不是本轮真实模型取数验收。阶段映射同时覆盖时间、澄清、口径、SQL、Gate、结果。

原始接口结果、截图、运行备份及检查日志保留在被 Git 忽略的位置，不纳入源码。

## 适用限制

字段血缘来自记录 SQL 的静态解析，查询成功或加工重算状态有独立证据。无法唯一解析、结构变化、未提交任务和无权限来源不生成字段箭头。历史读取有上限。条件字段不等同值依赖；复杂过程、动态 SQL 和未记录任务不推断血缘。

本轮只读验证已有电商验证数据；不宣称执行了新的真实 ROI 问题、生产任务或全量历史回填。访客会话输入政策由已有访客功能维护，本次地图能力与其权限边界兼容。
